## 0. 当前基线

- 进垃圾场时用原版函数预生成 24 格；点击只结算已生成结果；关窗重开不重 roll，离开再进才重生成。
- 已接：六类物品→密封箱、tier1/2 模组→机器、junkTable 排除、免疫不生成受伤格、受伤暂停/绷带续玩、右键标红、返回自动关窗。
- 最新线索规则：只在刚点格子的 8 邻内、未揭示且没给过线索的格子里选；受伤优先，否则价值最高；类型优先于稀有；给过线索的格子排除，顺延第二/第三。每条线索按点击格序号存一次，关窗重开/包扎恢复只回放原文，不重新抽取。
- 工具：手电电量就是 3 次「照一下」，照一格显示类型；放大镜每夜 1 次「细看」，显示具体物品名。两者都不扣下手。
- 额外掉落是附加标签：不再有「多」格；多件时仍是箱/机/物，标记变绿；线索指到多件格时会直接标成绿色箱/机/物并报「不止一件」。
- 音效：5 个自生成三角波短音（ui/blip/coin/hurt/end），走 ModHelper 音频通道。
- 自检：1 局 PASS=32 FAIL=0；跳过了无撬棍、机器、空格。
- 这一版尚未由玩家实测；下面 P0 的第一条就是它。

## 4. A：自动化验收（等项目大体做完）

> 触发条件：P0 清零、手电/扫描仪/材料文案接完、当前构建能完整玩一局。

- 脚本：`ScavGame/scripts/autotest.sh` + 一个本地小分析器。
- 流程：
  1. `dotnet build -t:Rebuild`；
  2. 确认游戏进程已退出，备份并部署 DLL/CSV；
  3. 启动游戏（Steam `-applaunch 4348910` 或 exe），等 `Player.log` 出现 `[ScavArcade] board generated`；
  4. 用输入自动化点开垃圾场 → 拾荒 → 按测试矩阵点击；
  5. 截图 + 解析 `Player.log`，检查不变量：
     - 24 条 `gen`，kind 分布合法；
     - 免疫 >0 时无 `kind=0`；
     - 没撬棍点箱：无 `attempts` 递减；
     - 细看：`charges` 递减、attempts 不变；
     - 受伤：`paused` → `resumed`；
     - 返回：窗口关闭、无异常堆栈。
  6. 输出 `ScavGame/test-reports/YYYYMMDD-HHMM.md`。
- 本地模型：
  - 先探测 Ollama（`127.0.0.1:11434`）、LM Studio、llama.cpp server；有视觉模型就用截图判断「线索/标记/按钮是否出现」，没有就退回正则 + 像素对比。
  - 模型只做「看截图/读日志给结论」，不直接改代码；结论写报告，人工确认后再修。
- 不能稳定自动化的：绷带使用（要打开背包）、撬棍/放大镜/免疫的装备准备、读档回滚。这些用调试台/存档预设，或留人工半自动。
- 安全：部署前备份现有 DLL；不写玩家存档；失败只回滚 Mods 目录。
