# 像素贴图手册（Probably Stolen 0.46D）

从三个模组的贴图工作里攒下来的做法：**还原蕨**（5 张植物/立绘）、**滤芯打印机**（1 张 48×48 机器）、
**下层药房**（2 张 16×16 药瓶药片）。下次做贴图先读这一页，能省掉一整轮返工。

> 结论先行：**尺寸和占格是硬规则，必须照原版；造型和明暗是画法，照原版机器的体积语言；生图模型只用来定构图和配色，像素永远手排。**

---

## 1. 三条路线，按尺寸选

| 贴图类型 | 尺寸 | 做法 | 案例 |
|---|---|---|---|
| 小图标（种子袋、药瓶、小药片、卷叶） | 16×16 | **照原版同尺寸模板逐像素重排**，模型只定图标形状 | `restoring_fern_seed`、`calm_agent` |
| 中等植物（标准叶/大叶） | 16×32、32×32 | **代码几何手排**（`Frond` + `Grid`），模型只给形状参考 | `restoring_fern`、`restoring_fern_l` |
| 机器 | 48×48（3×3 格） | **体积语言手排**：倒角顶面 + 凹槽 + 投影；模型给构图 | `fp_printer` |
| 水培立绘（`_p`，会被盖在机器上） | 48×64 | **模型定形 → 直接缩 → 压色板 → 摆位** | `restoring_fern_p` |

判断标准很简单：**画面里的细节能不能在目标像素数下活下来**。16×16 放不下玻璃瓶和瓶盖，48×48 放不下
模型的柔边和渐变，48×64 又画不下硬边的「横平竖直」叶片——所以四类走四条路，别互相套。

## 2. 硬规则（照原版，不商量）

| 规则 | 值 | 依据 |
|---|---|---|
| 画布尺寸 | **16 的整数倍** | 原版所有物品图都是 |
| 内容留边 | 物品/植物：四边 1 px 透明（叶子底边可为 0）；机器：**背景透明，深色描边贴着机身轮廓**（`blender`、`chem_finisher` 都是；`printer_off` 看着满幅只是因为机箱顶到画布边） | `dream_cap_s`、`fillerweed`、`blender` |
| 背景填充 | 植物类铺满 `(0,0,0,3)`；机器类四周透明 | 见 §3 |
| 锚点 | 中心 `(0.5, 0.5)` | 原版 `m_Pivot` 全 0.5 |
| 光源 | **左上亮、右下暗** | `dream_cap`、机器图集的明暗方向 |
| 外描边 | 1 px `#292234`；内部不描线，用暗色块分界 | 原版深色外缘 |
| 抗锯齿 | **禁止**，alpha 只有 0/255 | 原版像素画 |
| 色数 | 单张 ≤ 8 色（含描边、底色） | `dream_cap` 8 色、`hydroreed_filter` 10 色 |
| 文字/投影 | 不画 | 原版物品图没有 |

机器贴图的额外一条：**1 px 纯黑 + 1 px 藏青描边贴着机身轮廓**是外壳的固定结构，`items_tool2` 里每台机器都这么起手；**画布本身透明**，不要把整张 48×48 填成黑底（填了就变成图标外面一圈黑框）。

## 3. 占格是「采样」出来的，不是画多大就占多大

`GameItem.SetSpriteAndShapeFromMod`（`GameItem.cs:386-415`）按 `gridSize`（16，`UISettings.cs:12`）切格，
**取每个格中心点的 alpha**：`> 0` 记一格。所以：

- **植物**：细叶在格心可能是透明的 → 铺满 `(0,0,0,3)` 的底，格子数就永远等于画布尺寸 ÷ 16，不会缺角；
  （留边 1 px 不影响，因为格心不在边上。）
- **机器**：占格要 3×3，就保证**机身盖住 9 个格心**（`(8,8)`、`(24,8)`、`(40,8)` …），四周是不是透明无所谓。
  原版机器几乎都占满画布（`printer_off` 满幅、`blender` 左右留白但机身仍压住 9 个格心），
  所以它们既是 3×3 又有透明背景。**透明 ≠ 占格变小，透明格心才变小。**
- 想要别的占格就**改画布尺寸**（16×32 = 1×2，32×32 = 2×2），不要靠「画小一点」。

## 5. 工作流（机器与植物通用）

1. **导出原版**：UnityPy 读 `resources.assets`，按名字或所在图集筛 sprite（`FilterPrinter/scripts/extract_vanilla_sprites.py`、
   `ReductionFern/scripts/extract_sprites.py`），存到 `refs/vanilla/`。
2. **建色板**：对导出的图统计颜色，定 8 色左右；只从里面取色。
3. **参考图放大**：喂模型之前把原版贴图**最近邻放大 16×**（`ReductionFern/scripts/make_refs.py`）；
   直接给 16×16 原图，模型看到的是糊的。
4. **模型定构图**：一次 4 个 seed，长边至少 1024 px（`tools/qwen_gen.py` 的 `ICON = 1024²`；512 以下细节会塌）；
   提示词写清「像素块约 N 像素、深色描边、无渐变、无文字、无投影、无背景」。
   采样默认 `steps=25, cfg=1.0`（文档 API 图的口径，概念草稿可以到 30）。
5. **手排像素**：按 §6 的画法重绘到 16 px 网格。**模型稿不能直接缩到 48×48**（试过，内部会糊成一团）。
6. **量化**：所有像素落到色板（`pixify.py` 的 premultiplied 缩放 + 最近色量化；`place_portrait.py` 的压色板）。
7. **对图**：出 1× / 3× / 10× 三档对比图，和原版同角色贴图并排（`contact_sheet.py`）。
8. **记录**：`tools/qwen_gen.py` 会自动往 `refs/gen/manifest.json` 追加
   `route / prompt / 增强后全文 / negative / steps / cfg / seed / 尺寸 / 模型 / 输出 sha256`；手搓的图也要按同样的字段补一条。
   参考图必须配 `route`：给原版贴图当风格提示写 `route="style"`（画布仍按 `ICON`），
   要改造现有贴图写 `route="edit"`（画布跟着参考图走，9B 增强器默认开）。见 `BUILDING.md` §6.1。
   图标类**别开增强器**：它会把「9 个格心不透明、≤8 色、1px 描边」改写成散文，约束就丢了。

## 6. 每类贴图怎么画

### 6.1 机器 48×48（滤芯打印机）

**核心：机器必须有「顶面」。** 纯正面平描不管细节多少，在游戏里都像一张海报。两条路都行：

- **梯形顶面**：后沿窄、前沿宽（8 行左右，每行各收 3 px），顶面画装料井/散热格栅；
- **倒角机顶**（最终采用）：上两角 45° 台阶，顶面开装料井。

立体感的四个零件，缺一个就塌：

| 零件 | 画法 |
|---|---|
| 外壳 | 2 px 黑边 → 1 px `K` → 1 px `L`（上/左）或 `D`（下/右）斜面 |
| 凹槽（屏幕、出料口、装料井） | 远壁 `K`/`D`，一侧内壁 `L`，另一侧 `D`；**前沿一条 `L` 亮边横切过里面的东西**（被挡住的 1 px 就是深度） |
| 凸出部件（托盘、铭牌、指示灯板、脚） | 顶面 `L`、正面 `C`/`B`、底边 `c`，底下一行 `D`/`K` 投影 |
| 玻璃 | `G` 底 + 1–2 颗 `S` 反光点，不要整条高光 |

参考实现：`FilterPrinter/scripts/make_machine_sprite.py`（纯代码画，可复现，改一行就能换色/挪部件）。

### 6.2 植物 16×32 / 32×32（还原蕨）

- **16 px 宽放不下 5 枝**：标准叶是「1 片主叶 + 2 片暗叶」，大叶才用 5 枝叶束（根部聚拢、顶部张开）。
- 叶片必须是「1 行亮 + 1 行暗」的实体：上面一行 `G`，下面一行 `g` 且外端缩 1 px；**中间不要留 1 px 透明缝**，
  否则自动描边会把缝填成黑线，整张变网格（`fill_seams()` 专治这个）。
- 左右叶长**刻意不等**、右叶整体 `stagger=1` 下移，否则像代码生成的梯子。
- 中脉要弯（`x_profile`），死直的中脉 + 等长叶片 = 空。
- 描边是**先收集边界再统一涂**，边扫边涂会把整张画布淹掉（`pixel_art.outline()` 的注释写明了）。
- 大叶「变大」靠枝数和张开角度，不是把每片叶加宽。

### 6.3 16×16 小图标（种子袋、药瓶、药片）

- 照原版同尺寸模板逐像素重排：袋型、压边、内页、留白都和 `dream_cap_seed` 对齐。
- 模型稿只用来定「图标长什么样、用什么绿」，不要指望它给出能用的 16×16。
- 药瓶/药片这类圆形物体，允许先大图再缩，但要 **alpha 预乘**再缩（`Pharmacy/scripts/pixify.py`），
  否则透明边缘的颜色会渗进来，出现紫边/白边。

### 6.4 48×64 立绘（`_p`）

- 手排两次都被打回「横平竖直」——这个尺寸必须**模型定形 + 直接缩**：叶片斜、叶轴弯，缩下来才有有机感。
- 缩完要压回色板（模型的亮白叶尖会变成几颗方块，像花不像蕨），再按原版 `_p` 的 bbox 平移对齐、剪掉孤立茎尖。
- 立绘不画托盘（原版两张 `_p` 也没有），托盘交还给水培机。

## 7. 验收

**脚本**（每类都有现成的）：

| 检查 | 脚本 |
|---|---|
| 尺寸/留边/色数/描边/alpha（植物） | `ReductionFern/scripts/check_sprites.py`（改 `SIZES` 表即可用于新尺寸） |
| 与原版并排看 | `ReductionFern/scripts/contact_sheet.py` |
| 单张放大看 | `ReductionFern/scripts/ascii_sprite.py`、`compare_sprite.py` |
| 占格是否 3×3 / 1×2 | 读图算每 16 px 格心的 alpha（`FilterPrinter/scripts/make_machine_sprite.py` 出的图，用 6 行 python 核对过 9/9 格） |

**人眼**：一定要出 **1×** 的图。游戏里物品就是 1× 显示的，10× 好看不代表 1× 能认出来；
1× 下只剩剪影和大色块，所以「部件排布」和「明暗大关系」比细节更重要。

## 8. 踩过的坑

| 坑 | 症状 | 修法 |
|---|---|---|
| 平面正视图 | 细节很足，但像海报，和原版机器摆一起就露怯 | 加顶面/倒角、凹槽内壁、投影（§6.1） |
| 模型稿直接缩到 48×48 | 内部糊成色块，描边断成虚点 | 模型只定构图，像素手排 |
| 16 px 放太多枝 | 并成一坨 | 减枝数，用暗叶填缝 |
| 叶片间留透明缝 | 自动描边把缝填黑，整张变网格 | `fill_seams()` |
| 边扫边描边 | 描边泛滥，整张画布被吃掉 | 先收集边界，再统一涂 |
| 细茎被多数表决吃掉 | 茎不见了 | 直接缩（`--simple`），不做 2×2 表决 |
| 忘了 `(0,0,0,3)` 底 | 细叶只占半格，摆不进容器 | 铺满底（§3） |
| 参考图给原图 | 模型看到的是柔化图，出图不像素 | 最近邻放大 16×（§5） |
| 参考图给同角色原版贴图 | 造型容易被抄 | 想要原创造型就换参考（同图集别的机器/别的植物） |
| 换/加贴图后游戏拒载 | 日志报指纹不符 | 重新跑 `tools/trust_local.py`（PNG 也会进 folderHash） |
| 老存档里的物品不换皮 | 只有新造的物品是新贴图 | 在 `onLoaded` 里重定向 `spriteAtlasPath/spritePath` |
| 老档里的机器显示成「？」问号图 | `useSpriteFromMod=true` 但 atlas/path 被存档覆盖回原版值（`SaveManager.cs:182` 只覆盖路径、不清标志）→ `GameItemElement` 把原版 atlas 当 mod id 查 → `unknownSprite` | 判据改成三者同时匹配；兜底分支手动 `useSpriteFromMod = false` |
| 机器图标外面一圈黑框 | 把 48×48 画布整张填成不透明黑（误以为原版机器是"整张不透明"） | 画布透明，只保留沿轮廓的那 1 px 描边；机身盖住 9 个格心即可 |
| 工坊封面变糊 | `previewfile` 指到包内的 640×360 | vdf 的 `previewfile` 指 `mod/preview.png`（1280） |

## 9. 接进代码

```csharp
// 贴图文件：<mod>/Textures/Items/<名字>.png（文件名就是 sprite key）
// 游戏在 ModLoader.LoadTextures 里把它读成 mod.Sprites["<名字>"]（ModLoader.cs:1717-1750），
// 点过滤、无 mipmap；运行期由 GameItemElement 按 useSpriteFromMod 取（GameItemElement.cs:222-232）。
// 判据必须是「标志 + atlas + key」三者都对，不能只看 useSpriteFromMod（见 §8 的问号图一行）。
if (!(item.useSpriteFromMod && item.spriteAtlasPath == ModId && item.spritePath == "fp_printer"))
{
    item.SetSpriteAndShapeFromMod(ModId, "fp_printer");
}
if (item.spriteAtlasPath != ModId)                       // 兜底：目录里没有 PNG
{
    item.useSpriteFromMod = false;                       // 不清标志，原版路径会被当 mod id 查
    item.SetSpriteAndShape("Items/items_tool2", "printer_off");
}
```

- 旧存档按物品记 `spriteAtlasPath`/`spritePath`，换皮要在 `onLoaded` 里再指一次，否则老物品保持旧贴图。
  但**`onLoaded` 拿到的物品字段已经被存档覆盖过了**（`SaveManager.cs:182`），所以这一步不只是"再指一次"，
  而是唯一的修复点：此时 `useSpriteFromMod` 可能为 true 而 atlas/path 还是旧的原版值。
- 透明像素想点得中要 `alphaHitTestMinimumThreshold = 0`（还原蕨用到了）。
- 打包：`build.sh` / `package.sh` 要把 `Textures/` 一起复制并校验（尺寸、RGBA、DLL 里真的有这个 key；
  .NET 字符串是 UTF-16，`grep` 找不到，用 python 按 UTF-16LE 查）。
